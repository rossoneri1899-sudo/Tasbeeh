# Hands-free Tasbeeh — project notes

A web app that counts tasbeeh and adhkar by listening to the user recite. Hosted on GitHub Pages at `https://rossoneri1899-sudo.github.io/Tasbeeh/`. The owner uses an iPhone (Safari, added to the home screen) and shares the link with family and friends, often over WhatsApp, so it must work for anyone who opens a shared link on any phone.

## Constraints (read first)

- **The owner uses an iPhone and has no Mac.** No native iOS app; everything must work as a web page in iOS Safari (and Chrome on Android).
- **On-device only.** No audio may leave the phone. Do not add server-side speech APIs.
- **Do not use the Web Speech API** (`SpeechRecognition`). It is unavailable or blocked on iPhone; it was the first approach and it failed. Whisper in the page (the second approach) was a 40 MB download and inaccurate on short Arabic phrases.
- The owner tests on their phone and reports back. Keep changes easy to verify by hand, and say what was and wasn't tested.

## Releasing

- **Two channels.** `beta/` (`…/Tasbeeh/beta/`) is where changes go first. The live app is the same files copied to the repo root. Work in `beta/`, test, push; when the owner is happy, run `tools/publish.ps1` (copies `beta/` files to the root; the two manifests stay separate so the beta installs as "Tasbeeh β"), commit and push.
- **Bump `APP_VERSION` in `beta/app.js` on every release.** The page fetches `app.js` (no-store) on launch and whenever it returns to the foreground, and shows "A new version is ready" if the number differs, because iOS resumes home-screen apps from memory. The version is shown at the bottom of Settings. Live version numbers continue from the old app (11 → 12); the beta used b1–b4 before going live.
- `index.html` also carries `<!-- APP_VERSION='15' -->` so users still on the old single-file app (which looked for `APP_VERSION='…'` in index.html) get the update banner. Keep it in step with `app.js` for a while.
- Bump the version in `CACHE` in `beta/sw.js` when caching rules change. The service worker names its cache by channel (`tasbeeh-app-N` / `tasbeeh-beta-N`); the live one also deletes the old app's `tasbeeh-vN` cache and its Whisper `transformers-cache`.
- Pushing works from the normal shell (`git push origin main`); GitHub credentials are stored by Git Credential Manager. Commits are authored as Claude.

## How it works

- **Files:** `index.html` (markup + CSS), `app.js` (all app logic), `voice.js` (voice engine, no DOM), `adhkar.js` (generated data, don't edit by hand), `sw.js`, `manifest.webmanifest`, icons. Trimmed recordings live in the root `audio/` (`ROOT` = `../` inside `beta/`).
- **Voice engine (`voice.js`).** No speech recognition and no model download. The AudioWorklet (inline, Blob URL; ScriptProcessor fallback) only forwards raw audio after a 100–3800 Hz band-pass; `Voice.Resampler` → 16 kHz → `Voice.Front` makes a frame every 10 ms: 12 MFCCs (c0 dropped; each frame's mel spectrum floored at 30 dB below its peak so faint background noise doesn't change the shape), loudness in dB, voicing (peak normalised autocorrelation, 70–400 Hz, on the window decimated to 8 kHz) and pitch. Front keeps 12 s of audio for clipping recordings.
  - **Matching (a dhikr with ≥3 recordings): `Voice.Matcher`**, open-start subsequence DTW (SPRING), on templates trimmed to their voiced part (`Voice.template`), so back-to-back recitation works. Limit = 1.8 × the 90th percentile of leave-one-out scores between the user's own recordings, moved to the geometric mean with the closest wrong sound when there is one (other learned adhkar, except phrases contained in each other, and "not this" sounds). Synthetic tests put the user's own voice at ≤2.5× in noise and other phrases/speech at ≥3.5×. Sensitivity multiplies the limit 0.85–1.25×; the loudness gate is relaxed by 5 dB when matching.
  - **Learning by itself** (the owner found teaching every dhikr tedious): in rhythm mode each counted recitation of a dhikr (≤160 Arabic letters) is kept in `pend[k]`; Undo drops the last one. At `LEARN_N` = 5, `Voice.consistent()` keeps the ones whose median DTW distance to the others is ≤1.4× the typical (drops a cough or noise picked up by mistake). If ≥3 remain they become the dhikr's recordings and matching takes over.
  - **Teach it now** (optional): 2 s of quiet, then 5 recitations, cut by `Voice.Segmenter`. Also sets sensitivity (halfway between the room and the voice) and the pause length (60% of the user's breaths).
  - **Voice profile:** built from every recording of the user (any dhikr, plus optional "Train my voice", key `_voice`, 8 recordings of any adhkar) once there are 6. Rhythm-mode stretches are rejected if their median pitch is outside the user's range (5th–95th percentile × 0.75–1.3). Average MFCCs depend on the words more than the speaker (own voice saying an unheard dhikr scored further than another speaker), so they're only a loose check. So it ignores clearly higher or lower voices (other gender, children, many TV voices), not a similar voice.
  - **Rhythm mode (not learned yet): `Voice.Segmenter`.** Speech = loud enough above the adaptive background (fast down, slow up) and pitched within the last 120 ms, so hiss and clatter don't count. A stretch ends after `gap` ms (default 350) without speech; over 12 s it's rejected (talking, or a steady sound that becomes the background). Counts a stretch 280 ms–6 s long, or 0.45–2.2× the learned length once it has seen 3. Splitting long stretches is off by default: in b1 it split one slow SubhanAllah into 3–4 counts (its length guessed from letter count was 0.56 s; a deliberate recitation is 1.4–1.9 s). This mode can't tell words apart, and the hint under the beads says so.
  - **Long duas in rhythm mode (version 15):** `Voice.rhythmParams(letters, …)` decides the rules, and the test page uses the same function. Over 50 Arabic letters, a recitation ends only after `min(longGap, letters × 12 ms)` of quiet (setting "Pause at the end of a long dua", default 1.6 s), so breaths between verses are bridged. Before it has learned the dua's length, a stretch must be ≥ 45% of letters × 70 ms (Ayat al-Kursi/3 Quls ≈ 8 s), so one verse can't count. After 2 counts it uses 0.5–1.8× the learned length, and a stretch of 2–5× that length counts as that many (recited with too short a pause between). Found when the owner asked about a "2-second pause" suggestion: from b3 to version 14, a 4-verse dua recited 3 times counted 12. b1 had handled breaths in long duas, and the b3 rewrite dropped it without a test for it. Short adhkar are unchanged (0.35 s). Clips for learning can be up to 11.5 s (the Front's buffer is 12 s), so medium duas can be learned too.
  - **Whisper mode** (setting "I recite in a whisper", off by default; version 14): whispers have no pitch, so the Segmenter runs with `voiced: false` and the mic opens without noise suppression (phones remove whispers as noise). Whispered recordings are kept apart under key `<dhikr>~w` (`sk()`/`base()`); calibration compares whispers only with whispers. Without pitch, rhythm alone would count hiss, so nothing counts by itself until learned: a tap on the beads within 4 s of a whisper keeps it in `pend`, and after 5 matching takes over. Synthetic tests: 10/10 whispers across 8 seeds, hiss, other whispered dhikr and voiced talking rejected. Matches must now be ≥65% of a template's length (was 50%): the tail of a whisper sometimes matched a second time.
  - **Corrections:** Undo after a voice count saves that sound as "not this". Tapping the beads within 15 s of an uncounted sound offers "Save it" as a recording.
  - **Storage:** recordings in IndexedDB `tasbeeh2`/`samples` as 16 kHz Int16 audio `{k: dhikr key, neg, a}`. Recordings from the old app's "Train it on my voice" (IndexedDB `tasbeeh`, keyed by name) are imported once by matching names.
  - **Tests:** `tools/voice-test.html` (serve the repo root with `python -m http.server`, open `/tools/voice-test.html`) runs 34 synthetic-audio cases: pauses, slow, varied speed, back-to-back, quiet, hiss, similar vowels, one syllable changed, another dhikr, TV-like speech, noise bursts, clatter, voice profile, learning filter, whispers, long duas with breaths, medium duas. All pass. Add a case here for every counting bug found. Analysis + matching takes 0.4% of real time on a desktop. Real voices vary more than synthetic ones; tune the 1.8 factor from owner reports (the status line shows "match x of limit"). In the app, `window.__tasbeeh` exposes helpers for testing (`go(entryKey)`, `samples`, `calFor`); top-level `let`s like `front`, `seg`, `onListen` are reachable from the console for feeding synthetic audio.
- **Shared-link problems are handled up front:** `inAppBrowser()` detects WhatsApp/Instagram/Facebook/TikTok/etc., Android WebViews (`; wv)`) and iOS WKWebViews (no `Safari/` in the UA), and shows a banner with an "Open in Chrome" `intent://` link on Android or Safari steps on iPhone, plus Copy link. Mic errors map to short messages with a "How to fix" button that opens **Check my setup** (`diagnostics()`): a verdict, a 6 s live mic test, and copyable details (including voice profile and learned adhkar with their limits) for diagnosing friends' phones. The Share button sends instructions to open in Chrome/Safari.
- **Targets:** Target button under the beads → presets, own number, or No limit (stored as `NOLIMIT` = -1, `target()` returns Infinity, beads loop in 33s), applied to this dhikr / this list / everything. Stored per entry in `st.n` (only when different from the usual).
- **Content:** 215 dhikrs in 20 categories, all from Hisn al-Muslim plus 33 Quranic duas and a few short phrases. Built by `tools/build_adhkar.py` from rn0x/Adhkar-json (Arabic + recordings), the Hugging Face dataset M-AI-C/hisnulmuslim (transliteration, English, references; matched to the Arabic by text, since the numbering is off by one in places) and api.alquran.cloud (Uthmani text, Sahih International). The script holds all curation: category lists, cuts of narrative text (`start`/`end` markers on diacritic-free text), evening wordings written out from the book's notes, and plain-English titles (`NAMES`). `python tools/fetch_sources.py <dir>` downloads the sources; `python tools/build_adhkar.py <dir> beta/adhkar.js review.txt` builds, then read review.txt. The output is reproducible byte for byte.
- After-prayer tasbeeh is 33/33/34 (the owner's choice), not Hisn al-Muslim's 33/33/33 + La ilaha illallah.
- **Recordings:** the 16 trimmed files in `audio/` are used where they exist (Hamad Al-Duraihim, hisnmuslim.com, via rn0x/Adhkar-json, free to use; trimmed to the dhikr only and re-transcribed to confirm). 144 more stream on demand from jsDelivr (`AUDIO_CDN`, pinned to an rn0x commit); those are untrimmed, so some start with the spoken chapter title. Quran duas play the full verse (Mishary Alafasy, everyayah.com). The service worker never intercepts `.mp3` (media needs 206 range responses).
- **Storage:** `localStorage` keys prefixed `tb2.`. On first run the old app's `history` is imported so streaks continue. Counts reset at local midnight; history keeps 800 days. iOS can clear storage for home-screen web apps unused for a while; `navigator.storage.persist()` is requested.
